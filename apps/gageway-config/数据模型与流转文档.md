# 路由网关系统 - 数据模型与流转文档

## 系统概述

本系统是一个路由网关配置管理平台，支持多应用的路由配置、版本管理、权限控制和审计日志功能。系统采用双层架构：路由级别控制整个路由的启用/停用，版本级别控制具体的配置内容和上线状态。

## 核心数据模型

### 1. 应用管理模块

#### Application (应用表)
```typescript
{
  id: string          // 主键
  name: string        // 应用名称
  code: string        // 应用唯一标识码 (unique)
  domain: string      // 绑定域名 (unique)
  description?: string // 应用描述
  status: ApplicationStatus // 应用状态: ACTIVE | INACTIVE | MAINTENANCE
  createdAt: DateTime
  updatedAt: DateTime
  createdBy?: string  // 创建者ID
}
```

### 2. 路由配置模块

#### Route (路由主表)
```typescript
{
  id: string          // 主键
  applicationId: string // 应用ID
  name: string        // 路由名称
  path: string        // 路由路径
  method: HttpMethod  // HTTP方法: GET | POST | PUT | DELETE | PATCH | HEAD | OPTIONS | ALL
  priority: number    // 优先级
  status: RouteMainStatus // 路由级别状态: ACTIVE | INACTIVE
  publishedVersionId?: string // 当前发布的版本ID
  createdAt: DateTime
  updatedAt: DateTime
  createdBy?: string
}
```

**关键特性：**
- 每个路由路径一条记录
- `status` 控制整个路由是否生效
- `publishedVersionId` 指向当前线上版本
- 支持路径、方法和应用的唯一约束

#### RouteVersion (路由版本表)
```typescript
{
  id: string          // 主键
  routeId: string     // 路由ID
  version: string     // 版本号
  configType: ConfigType // 配置类型: REDIRECT | OSS
  status: RouteStatus // 版本状态: DRAFT | ACTIVE | INACTIVE | TESTING
  baseVersionId?: string // 基于哪个版本创建
  publishedAt?: DateTime // 发布时间
  publishedBy?: string   // 发布者ID
  createdAt: DateTime
  updatedAt: DateTime
  createdBy?: string
}
```

**关键特性：**
- 每个版本一条记录
- 支持版本继承关系 (`baseVersionId`)
- `status` 控制版本状态
- 与配置详情表的一对一关系

#### RedirectConfig (重定向配置表)
```typescript
{
  id: string
  versionId: string   // 路由版本ID (unique)
  targetUrl: string   // 目标URL
  statusCode: number  // HTTP状态码 (默认302)
  queryForward: boolean // 是否转发查询参数
  headers?: Json      // 自定义响应头
}
```

#### OssConfig (OSS映射配置表)
```typescript
{
  id: string
  versionId: string   // 路由版本ID (unique)
  bucket: string      // OSS存储桶
  objectKey: string   // 对象键（文件路径）
  region?: string     // 区域
  endpoint?: string   // 自定义端点
  cacheControl?: string // 缓存控制
  contentType?: string  // 内容类型
  headers?: Json      // 自定义响应头
}
```

### 3. 权限管理模块

#### AppPermission (应用权限表)
```typescript
{
  id: string
  userId: string      // 用户ID
  applicationId: string // 应用ID
  role: AppRole       // 角色: OWNER | ADMIN | EDITOR | VIEWER
  permissions: PermissionType[] // 权限列表: READ | WRITE | DELETE | DEPLOY | ROLLBACK | MANAGE
  createdAt: DateTime
  updatedAt: DateTime
  grantedBy?: string  // 授权者ID
}
```

### 4. 版本控制模块

#### ConfigVersion (配置版本表)
```typescript
{
  id: string
  applicationId: string // 应用ID
  routeId?: string     // 路由ID（为空表示应用级版本）
  versionId?: string   // 路由版本ID
  version: string      // 版本号
  action: VersionAction // 操作类型: CREATE | UPDATE | DELETE | DEPLOY | ROLLBACK | UNPUBLISH
  description?: string // 版本描述
  configData: Json     // 配置数据快照
  createdAt: DateTime
  createdBy: string    // 操作者ID
}
```

#### AuditLog (操作日志表)
```typescript
{
  id: string
  userId: string       // 操作用户ID
  applicationId: string // 应用ID
  action: string       // 操作类型
  resource: string     // 操作资源
  resourceId: string   // 资源ID
  details?: Json       // 操作详情
  ipAddress?: string   // IP地址
  userAgent?: string   // 用户代理
  createdAt: DateTime
}
```

## 数据流转架构

### 1. 双层状态管理

```
Application
├── Route (路由级别状态)
│   ├── status: ACTIVE/INACTIVE    # 控制路由是否生效
│   ├── publishedVersionId         # 指向当前线上版本
│   └── RouteVersion (版本级别状态)
│       ├── status: DRAFT/ACTIVE/INACTIVE/TESTING  # 版本状态
│       ├── configType: REDIRECT/OSS               # 配置类型
│       └── 配置详情 (RedirectConfig 或 OssConfig)
```

### 2. 版本生命周期

```
[创建] --> DRAFT --> [发布] --> ACTIVE --> [下线] --> INACTIVE
    ↑                             ↓
    └─────────[删除草稿]    [重新上线]─────┘

注意：
- 只能有一个 ACTIVE 版本
- 可以有多个 DRAFT 版本
- INACTIVE 版本可以重新上线
```

### 3. 核心业务流程

#### 路由创建流程
1. **创建路由** → `Route` 表插入记录，`status = ACTIVE`
2. **创建版本** → `RouteVersion` 表插入记录，`status = DRAFT`
3. **配置详情** → 根据 `configType` 插入 `RedirectConfig` 或 `OssConfig`
4. **记录日志** → `AuditLog` 记录操作

#### 版本发布流程
1. **版本切换** → 更新旧版本 `status = INACTIVE`
2. **激活新版本** → 更新新版本 `status = ACTIVE`，设置 `publishedAt`
3. **更新路由** → 更新 `Route.publishedVersionId`
4. **创建快照** → `ConfigVersion` 记录版本快照
5. **记录日志** → `AuditLog` 记录操作

#### 路由状态控制
1. **路由级别** → `Route.status` 控制整个路由是否生效
2. **版本级别** → `RouteVersion.status` 控制版本状态
3. **配置级别** → 具体的重定向或OSS配置

### 4. API 数据流转

#### 获取路由列表
```
GET /api/applications/{appId}/routes
├── 查询 Route 表（包含 publishedVersion）
├── 格式化数据：
│   ├── route.status → 路由状态
│   ├── publishedVersion.status → 版本状态
│   └── 配置详情 → RedirectConfig/OssConfig
└── 返回分页数据
```

#### 版本管理
```
GET /api/applications/{appId}/routes/{routeId}/versions
├── 查询所有版本（按创建时间倒序）
├── 排序逻辑：
│   ├── 1. 草稿版本优先
│   ├── 2. 线上版本次优先
│   └── 3. 同类型按时间倒序
└── 返回版本列表
```

#### 版本切换
```
POST /api/applications/{appId}/routes/{routeId}/versions/{versionId}/publish
├── 事务处理：
│   ├── 1. 旧版本设为 INACTIVE
│   ├── 2. 新版本设为 ACTIVE
│   ├── 3. 更新 Route.publishedVersionId
│   ├── 4. 创建 ConfigVersion 快照
│   └── 5. 记录 AuditLog
└── 返回操作结果
```

### 5. 权限控制流程

```
用户操作请求
├── 身份验证 (NextAuth)
├── 权限检查 (AppPermission)
│   ├── READ: 查看权限
│   ├── WRITE: 编辑权限
│   ├── DEPLOY: 发布权限
│   ├── ROLLBACK: 回滚权限
│   └── MANAGE: 管理权限
├── 操作执行
└── 审计记录 (AuditLog)
```

### 6. 前端状态管理

#### 主表格数据结构
```typescript
interface RouteData {
  // 路由基本信息
  id: string
  name: string
  path: string
  method: string
  
  // 双层状态
  status: 'ACTIVE' | 'INACTIVE'          // 路由级别状态
  versionStatus: 'DRAFT' | 'ACTIVE' | 'INACTIVE' | 'TESTING' // 版本状态
  
  // 配置信息
  configType: 'REDIRECT' | 'OSS'
  targetUrl?: string
  ossPath?: string
  
  // 版本信息
  publishedVersionId?: string
  publishedAt?: string
  publishedBy?: string
  
  // 时间信息
  createdAt: string
  updatedAt: string
}
```

#### 操作按钮逻辑
```
主表格操作列：
├── 路由状态切换: "启用路由" / "停用路由"
└── 更多操作菜单:
    ├── 编辑路由
    ├── 版本管理
    ├── 操作记录
    ├── 上线记录
    ├── 测试路由
    └── 删除路由

展开行操作列：
├── 发布版本 (仅草稿状态)
├── 操作记录
├── 上线记录
├── 编辑配置
└── 版本管理

版本管理弹窗：
├── 直接上线 (草稿版本)
├── 切换上线 (已发布版本)
└── 当前线上 (线上版本)
```

## 关键设计原则

### 1. 数据一致性
- 使用数据库事务确保版本切换的原子性
- 外键约束保证数据完整性
- 唯一约束防止重复数据

### 2. 版本管理
- 支持版本继承和分支
- 保留完整的版本历史
- 快照机制确保配置可追溯

### 3. 权限控制
- 基于角色的权限控制 (RBAC)
- 细粒度的操作权限
- 完整的审计日志

### 4. 可扩展性
- 模块化的数据结构
- 支持新的配置类型
- 灵活的权限模型

### 5. 用户体验
- 双层状态清晰分离
- 直观的操作界面
- 丰富的状态提示

## 常见操作场景

### 场景1：新建路由
1. 用户填写路由信息（名称、路径、方法等）
2. 选择配置类型（重定向或OSS映射）
3. 填写具体配置信息
4. 系统创建 Route + RouteVersion + Config 记录
5. 初始状态：路由启用，版本为草稿

### 场景2：编辑路由配置
1. 用户点击编辑按钮
2. 系统基于当前版本创建新的草稿版本
3. 用户修改配置信息
4. 系统更新草稿版本的配置
5. 用户可选择发布或保存为草稿

### 场景3：版本切换
1. 用户在版本管理中选择目标版本
2. 系统显示确认对话框
3. 用户确认后执行版本切换
4. 系统更新版本状态和路由指针
5. 记录操作日志和创建配置快照

### 场景4：路由停用/启用
1. 用户点击停用/启用按钮
2. 系统更新路由级别状态
3. 不影响版本配置和版本历史
4. 记录操作日志

## 总结

该系统通过精心设计的数据模型和流转机制，实现了路由配置的精细化管理。双层状态设计既保证了系统的灵活性，又确保了操作的安全性。完整的版本控制和审计机制为生产环境提供了可靠的保障。

核心优势：
- **清晰的职责分离**：路由级别控制生效状态，版本级别控制配置内容
- **完整的版本管理**：支持草稿、发布、回滚等完整生命周期
- **灵活的配置支持**：支持重定向和OSS映射两种配置类型
- **强大的权限控制**：基于角色和操作的细粒度权限管理
- **全面的审计追踪**：所有操作都有完整的审计日志
